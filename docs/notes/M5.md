# M5 notes: voice agent and L3 suite

**Decision:** websocket for the automated L3 suite (and the base for M6 telephony),
SmallWebRTC for the browser demo and D2. The maintainer ruled on 2026-10-10. The pipeline
is shared, so a second transport costs almost nothing.

## What was built

- **`lab/voice/pipeline.py`:** transport in, Silero VAD, Whisper (`small.en`, CPU int8),
  Pipecat's user-turn processor (VAD start with barge-in, speech-timeout end of turn, idle
  re-prompt), the L2 `TextAgent` as a processor, Kokoro, transport out. `TurnLog` keeps
  per-stage timestamps, STT fragments, interruptions and idle prompts.
- **`lab/voice/caller.py`:** the in-process websocket voice session, plus an open-line test
  caller. It sends 20 ms frames in real time, silence between utterances, and timestamps
  every frame it receives.
- **`lab/voice/audio_synth.py` + `golden/personas.yaml`:** caller audio from Kokoro. There
  are two clean voices, fast speech, British and Spanish-accented voices, cockpit noise
  (piston harmonics plus pink noise at 5 dB SNR), and a hesitant caller with a 1.2 s
  mid-question pause. Audio is deterministic and cached.
- **`tests/L3_voice`:** 89 tests in three groups:
  - variants: every golden case's spoken variants, voices alternating;
  - personas: four canonical questions in each non-clean persona;
  - behavior: barge-in and caller silence.

  Each turn records a WER and the STT-equivalence judge against what the caller actually
  said, a one-turn check, all the L2 judges on the answer, and an attribution tag. A
  run-level test gates the median time to first audio, measured at the caller.
- **`lab/harness/attribution.py`:** one primary root-cause tag per failed case. There are
  two deviations from the plan's order:
  - POLICY and TURN_TAKING run before the retrieval rules: an answer to the wrong
    question, or to half of one, says nothing about retrieval.
  - Four tags are new, all called for by M4's results: AGENT_QUERY, CORPUS_TRAP,
    GENERATION_INCORRECT and TERMS.

  LATENCY is primary only when the content passed.
- **`lab report`:** a static HTML page covering L1, L2 and L3. It shows failures by tag,
  the persona table and the behavior scenarios, and a per-case drill-down with judge
  reasons, sources and both sides' audio. Attribution is recomputed with the current rules
  on every build.
- **`lab serve-voice`:** Pipecat's development runner and prebuilt UI over SmallWebRTC, on
  http://localhost:7860. `scripts/check_serve_voice.py` calls it through the real HTTP
  signaling with an aiortc caller.
- **CI:** one spoken case, plus barge-in and silence, with a 0.5B CPU agent and the judge
  off; then `lab report`.

## What L3 found in the voice path

Each of these surfaced in a full or slice L3 run. None was visible in L1 or L2.

1. **Answering half a question.** The agent processor fired on every Whisper segment, and
   Whisper segments at every VAD pause, so "Is synthetic vision on by default? / And how do
   I turn it on?" got two answers (23 of 86 turns). It now collects segments and answers
   once, on the user-turn processor's end-of-turn frame.
2. **The end-of-turn detector never saw a transcript.** It sat before Whisper in the
   pipeline. Its speech-timeout strategy waits for a transcript, so every turn ended on its
   5 s give-up timer, and STT p50 read exactly 5.0 s. It now sits after Whisper. There it
   announces the end of a turn just before forwarding the transcript that decided it, so
   the agent processor waits briefly for that last fragment rather than trusting frame
   order.
3. **Whisper froze the pipeline (a Pipecat 1.12 bug).** `WhisperSTTService.run_stt` runs
   faster-whisper's `transcribe()` in a thread, but `transcribe()` returns a lazy
   generator, and the decoding happened in the `for segment in segments` loop on the event
   loop. For the ~2 s of each transcription, VAD was deaf: a caller who resumed after a
   short pause looked silent, and the turn ended mid-question. `EagerWhisperSTTService`
   decodes inside the worker thread. **Worth reporting upstream.**
4. **Whisper runs behind real time on CPU,** about 2 s per segment, while the end-of-turn
   strategy needs only one transcript. The agent processor now waits until the caller
   isn't speaking and every segment is transcribed (capped at 10 s). Transcripts that
   arrive after their turn was answered are dropped, so they don't leak into the next
   question.

There was also one harness bug: the STT judge compared transcripts with the *canonical*
question rather than the words actually spoken, so the golden set's own paraphrases were
tagged STT_MISHEARD. It now compares against what was said. WER decides only when the
judge is off, because it counts "PI-FEs" for "pie efis" as two errors even though the
meaning survives.

Persona slice after fixes 3 and 4: 11 of 12 two-sentence questions arrived whole, up from
4 of 12. The miss was the first case after warm-up, which waited 13 s; that's a known edge.

## Baseline: `baselines/L3/2026-10-10.json`

What it says:

- **Voice isn't the main problem; the agent still is.** STT accounts for 5 of 86
  failures. Those five are real: "SVS" heard as "SV? as", "pyEfis" as "PyFees", the
  hesitant pause eating "GPU", and the noisy and accented callers losing the first
  sentence. The agent stages carry the rest, the same weaknesses L2 showed.
- **The spoken phrasing matters more than the audio.** On the clean voices, 12 cases pass
  in L2 (the canonical question) but fail in L3, mostly with AGENT_QUERY. The spoken
  variant ("how do I get to the engine page") leads the agent to a worse search than the
  written question does. That's a phrasing effect, not an audio one: the transcripts are
  accurate. An L2 run on the spoken variants' text would separate the two exactly.
- **Cockpit noise is the hardest persona** (WER 0.30, 0 of 4). It costs the caller words,
  not whole turns.
- **Latency is 10x over budget.** TTS to first audio (5.9 s) is now as large as the agent's
  share: Kokoro on CPU synthesizes the first sentence before any audio flows. The levers
  are unchanged: first-sentence streaming TTS, GPU Whisper, streaming the agent's answer.

## Acceptance

- *A person can talk to the agent in a browser:* `lab serve-voice` serves the UI, and an
  aiortc caller over the real HTTP signaling got a correct spoken answer ("What license is
  pyEfis under?": GPL 2.0 or later). **A person with a microphone still has to try it.**
- *The L3 suite runs the golden set through audio:* yes, 86 turns in 7 personas, plus
  barge-in and silence.
- *The report shows per-layer scores and attribution tags:* `lab report`.

## Decision point: L3 transport spike (2026-10-10)

`scripts/spike_transport.py` sends one Kokoro-synthesized question ("Do I need a GPU to run
pyEfis?", `am_michael`) through the same voice pipeline over two transports. Each caller
streams the WAV in real time in 20 ms frames, then keeps sending silence the way an open
phone line does, and records the reply.

The pipeline (`lab/voice/pipeline.py`) is shared: transport in, Silero VAD, faster-whisper
`small.en` (CPU int8), the L2 `TextAgent`, Kokoro, transport out. The agent stage is the L2
agent wrapped as a Pipecat processor rather than Pipecat's own LLM service. A voice turn
therefore runs the identical prompt, model, MCP tools and speech normalizer that L2 tests,
which is what lets attribution compare an L3 case with the same case in L2.

| | Websocket (Pipecat server transport + protobuf) | SmallWebRTC (aiortc loopback caller) |
|---|---|---|
| End to end | works | works |
| STT / agent / TTS to first audio (warm) | 2.0 s / 6.2 s / 4.1 s | 2.0 s / 6.1 s / 4.3 s |
| Caller stops talking to first audio back | 12.3 s (client measured 12.5 s) | 12.3 s (client measured 12.7 s) |
| Reply audio, re-transcribed | intact | intact (through Opus) |
| Test caller | ~40 lines: `websockets` plus the protobuf serializer, exact frame timing | ~70 lines: an aiortc track with paced recv(), SDP exchange, codec in the path |
| Browser demo / D2 | needs a custom JS client (mic capture, no echo cancellation) | Pipecat's prebuilt browser UI; echo cancellation; works from a phone browser |
| Telephony (M6) | same family: SIP-to-media-stream bridges and Pipecat's telephony serializers are websocket | a separate bridge |

Findings either way:

- **Latency is the headline:** 12.3 s against the 1.5 s time-to-first-audio budget. The
  levers, roughly in order of size: TTS that starts on the first sentence (Kokoro on CPU
  waits for the whole chunk), GPU Whisper (CTranslate2 CUDA on Pascal is untried and may hit
  the same driver wall as Ollama), streaming the agent's final answer, and fewer tool rounds.
- **STT mishears the product name:** "pyEfis" became "pi-effies" in every run. The agent
  still found the right section. Whisper's `hotwords` and `initial_prompt` settings are the
  obvious fix, and STT_MISHEARD attribution will measure it.
- **TTS mispronounces it:** Kokoro says "pyEfis" as "pi Fe's". A pronunciation lexicon in
  `lab/agent/speech.py` belongs on the TTS side.
- **The first turn after idle took 25.5 s** while Ollama reloaded the model (its keep-alive
  is 5 minutes). The L3 suite warms up first, as L2 does.
- Kokoro logs a non-fatal "TTS context completed with no audio" error once per turn. It's
  harmless; to investigate.
- Windows `time.monotonic()` ticks in 15.6 ms steps; the pipeline timestamps use
  `perf_counter`.
