That's 1,940 chunks in about 10 minutes, roughly 3 chunks/s. Re-running with nothing changed takes
0.5 s per source and writes nothing. Query latency, including embedding the question, is 80–115 ms
against a 300 ms budget.

## Design choices

- **Idempotency key** = commit sha + a fingerprint of the source's config (paths, excludes, origin,
  chunker version). Keying on the sha alone would miss a `sources.yaml` edit. A new key upserts
  the new points and then deletes the source's stale ones, so the source is never absent mid-update.
  This was checked by simulating a key change (point count unchanged) and a forced re-index under
  the same key (overwrites in place).
- **Embedded text = repo + path + heading path + body.** The stored `text` is the body alone.
  The heading context is what lets a short "Hardware" section match "do I need a GPU".
- **YAML comment blocks** belong to the key they directly precede. A blank line ends a block.
- **RST titles** follow docutils rules, including "an overline must be at least as long as the
  title". pyEfis' README uses `'''` as a makeshift code fence around a command, and that rule is
  what keeps it from becoming a heading.
- The code lives under `lab/ingest/`, not the plan's top-level `ingest/`, so the project has one
  import namespace (`lab.*`). Retrieval, agent and harness will follow the same pattern.

## Corpus corrections vs. the draft plan

- FIX-Gateway's docs are in `doc/`, not `docs/`.
- Excluded from the fork: `docs/archive/**` (session handoffs) and `docs/images/**` (screenshot
  evidence READMEs). `CLAUDE.md` is excluded by basename everywhere, which also covers
  `makerplane-data/configurator/CLAUDE.md`.
- Only `.md`, `.rst`, `.yaml` and `.yml` are parsed. That drops PDFs, `conf.py` and Makefiles.

## Findings that matter for M3 (golden set)

- **Look-alike noise is already real.** "Do I need a GPU to run pyEfis?" ranks the fork's internal
  `docs/perf_baseline_gpu_required.md` (0.798) above the README's *Hardware > Minimum* section
  (0.769). The fork's `docs/` holds many engineering plans and specs next to the user docs. The plan
  worried the corpus might be too easy; it isn't.
- **VER-001 needs a ruling.** Upstream `makerplane/pyEfis` `docs/requirements.md` has SVS
  *requirements* (EFIS-SVS-001…010), so "does upstream have SVS?" isn't answerable from "upstream
  never mentions it". The expected answer has to separate specified from shipped.
- The fork's README and `docs/getting_started.rst` are near-duplicates of upstream's. That's good
  material for `RETRIEVAL_WRONG_VERSION`.

## Running the full corpus faster

CPU embedding is the bottleneck. The GTX 1080 Ti isn't visible to Docker here. Options, from
easiest: run Ollama natively on Windows (it uses the GPU) and point `LAB_OLLAMA_URL` at it, or
enable GPU passthrough in the container runtime and use `docker-compose.gpu.yml`.
