# M4 notes: text agent and L2 suite (2026-10-10)

## What was built

- **`lab/agent/`:** the agent under test.
  - `prompts/system.md`: scope (search before answering, docs only), refusal policy, clarify
    rule, and speakability rules. It sets policy and doesn't encode golden answers.
  - `text_agent.py`: the tool loop. It discovers tools from the MCP server (`lab serve-mcp`,
    the same server the Pipecat agent will use in M5). Config `agent.tools` picks which tools
    the model sees. `agent.hidden_args` takes `k`, `repo` and `origin` out of the schema; the
    harness sets them. After `max_tool_rounds` the model has to answer without tools. Each
    `AgentTurn` records tool calls with ranked hits, the chunks shown to the model, per-stage
    timing and token counts.
  - `llm.py`: Ollama `/api/chat` and the Anthropic API behind one message shape, so the hosted
    comparison path (and the D2 demo) is a config change.
- **`lab ask`:** runs the agent from the command line (`lab ask HW-003 "free text" --model …`).
- **`lab/harness/judges.py` + `rubrics/`:** policy (answer / decline / clarify),
  correctness against the reference answer and notes, speakability, and STT equivalence (for
  M5). Each judge uses Haiku 4.5 through `messages.parse` with a fixed
  `{verdict, score, reason}` schema. Ragas faithfulness and answer relevancy go through Ragas'
  adapter, with relevancy embedded by the lab's own nomic model.
- **`tests/L2_agent/`:** one generated test per golden case (all 35):

  ```
  Ask Agent                              (records the turn; also searches the plain question)
  Judge Answer                           (every judge for the case, concurrently; never fails)
  Agent Should Have Searched             (answer cases)
  Agent Search Should Find Gold Source   (fails only if the agent's query misses gold
                                          that the plain golden question finds)
  Agent Should Answer | Decline | Ask For Clarification
  Answer Should Contain Expected Terms
  Answer Should Be Correct / Faithful    (answer cases)
  Answer Should Be Speakable
  ```

- **`lab calibrate export | score`:** a blind grading worksheet (no judge verdicts in it)
  and the agreement report. Details are under *Judge calibration*.

## Environment

- **Native Ollama on the 1080 Ti runs through Vulkan, not CUDA.** Ollama 0.40.2's CUDA
  runner dies with "the provided PTX was compiled with an unsupported toolchain". The NVIDIA
  driver (560.94, CUDA 12.6) is older than the toolchain Ollama's Pascal (compute 6.1) PTX was
  built with. Vulkan offloads all 37 layers, and llama3.1:8b answers a 3k-token prompt in
  about 1.4 s. A driver update would probably bring CUDA back.
  Start it on a port that doesn't clash with the Docker Ollama:

  ```powershell
  $env:OLLAMA_HOST="127.0.0.1:11435"; $env:CUDA_VISIBLE_DEVICES="-1"; $env:OLLAMA_VULKAN="1"
  & "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" serve
  ```

  `.env` sets `LAB_AGENT_LLM_URL=http://localhost:11435`. Embeddings stay on the Docker
  Ollama, so the index and L1 are unchanged.

## Choosing the agent model

| Model | Behavior on the first four cases |
|---|---|
| qwen3:8b, `think: false` | Never called `search_docs`, even with the one-argument schema. It answered from memory and invented an altimeter procedure. |
| llama3.1:8b | Searched every in-scope question. With the full schema it sent `origin: "null"` as a string, got a validation error, and then told the caller to pick a fork. Hiding the filter arguments fixed it. |

llama3.1:8b is the default. qwen3 with thinking on was not tried: thinking adds latency that a
voice turn can't afford, but it is a config switch (`think: true`) if M5 has room.

### What the baseline says

**Faithful but wrong is the headline.** Faithfulness is 0.92 but correctness is 0.48. The
agent mostly says what the retrieved text says; the retrieved text is often the wrong text.
The trap documents recorded in M3 now produce trap answers:

- **HW-005:** about 91 GB, from the stale README. The reference is about 120 GB.
- **INST-001:** install with snaps on Raspbian bullseye, from the stale `INSTALLING.md`.
- **VFR-001:** run `MakeCIFPIndex.py` and edit `[Screen.PFD]`: both README defects, repeated.
- **DATA-002:** a developer CLI procedure instead of the Data Status screen. The agent's
  query missed the Pilot's Guide that the plain question finds, so it counts as a query
  regression.

The rest of the 15 incorrect answers are omissions (ARCH-002 misses the port number,
SVS-002 the data origins) or answers to the wrong question (DEV-002 gives a visual-test
command, not `make test`). This is the split M5's attribution needs: the faithful-but-wrong
answers belong to the corpus, and the unfaithful ones belong to generation.

**Speakability is the weakest layer at 0.54.** The 8B model quotes `pip install -e
'.[qt,svs]'`, YAML keys, markdown bold and file paths despite the prompt. Four of the five
procedural cases fail; only DEV-003 passes.

**Policy is nearly clean.** All four out-of-scope cases decline, including the in-flight
emergency (OOS-004) and the prompt-injection case. CLAR-001 ("how do I set it up?") searched
and answered with the upstream `setup.py` install instead of asking which part.

**Query regressions (CTRL-003, DATA-002, OOS-001):** the agent rewrote the question into a
worse query than the caller's words. Only an agent-level test can see this; L1 searches the
plain question.

## Judge calibration (pending the maintainer's grades)

`golden/calibration/L2-2026-10-10.yaml` has 20 cases: all six decline and clarify cases, plus
14 answer cases picked by id hash, never by verdict. It also has the five chunks retrieved for
DATA-001, DEV-003 and FGW-003, the M3 cases where Ragas context precision disagreed with the
deterministic score. Grade it blind, then:

```sh
uv run lab calibrate score golden/calibration/L2-2026-10-10.yaml
```

That prints agreement and Cohen's kappa per judge, each disagreement with the judge's
reason, and human versus Ragas context precision for the three L1 cases. **The baseline's
judged numbers are provisional until it is scored.**

Judge errors already visible on inspection. They were not used to change the rubrics, which
would tune the judge on its own test set:

- **CLAR-002, policy:** "pyEfis is on by default…" is an answer, but the judge returned
  `clarify` because the *question* was ambiguous. It graded what the response should have
  done, so the case passed when it should have failed. Behavior accuracy is really 0.94, not
  0.97.
- **HW-002, faithfulness 0.25:** a correct answer, read almost verbatim from the retrieved
  README section. The same kind of Ragas noise M3 saw in context precision.
- **VER-001 vs VER-002, correctness:** VER-001 fails for leaving out "fork only", but VER-002
  passes despite leaving out "experimental", which its reference also requires. Omission is
  graded inconsistently.
- **FGW-001, correctness:** failed for "immutable once loaded". FIX-Gateway's README says
  "the database structure is immutable", which is true and doesn't contradict "plugins read
  and write" values; the judge conflated structure with contents.

Rubric changes wait for the calibration scores, and then get re-scored against the same
worksheet.

## Engineering notes

- **Prompt caching doesn't apply to the judges.** Haiku 4.5's minimum cacheable prefix is
  4,096 tokens, and each rubric is a few hundred. The Batch API (50% off) remains the cost
  lever for nightly runs (M7). At $0.37 a pass, it isn't needed yet.
- **`messages.parse` isn't covered by the `lab/judge.py` sampling shim.** The judges pass
  `temperature` in `extra_body` themselves and count usage through `judge.record_usage`.
- **Ragas AnswerRelevancy** runs with `strictness=1`: at temperature 0 its three generated
  questions repeat anyway.
- **Substring term checks can't see negation.** "does not indicate that pyEfis itself is
  certified" tripped OOS-001's forbidden "is certified", so the term was removed. See
  `golden/README.md`.
- **CI** runs L2 on four cases with `qwen2.5:0.5b` on CPU and the judge off. That checks the
  harness (MCP tool discovery, the loop, the report), not quality; the 0.5B model doesn't even
  search.

## For M5

- Attribution can use the L2 split directly: `GENERATION_UNFAITHFUL` when faithfulness is low,
  a corpus tag when the answer is faithful but incorrect and a trap was retrieved, and agent
  query regressions as their own tag.
- Speakability is where the voice pipeline will hurt most. Try a speech-oriented rewrite of
  the prompt, or a second "speak it" pass, after calibration confirms the speakability judge.
- A whole text turn takes 5.5 s at p50 before any STT or TTS, against a 1.5 s
  time-to-first-audio budget. Streaming the final answer, and fewer tool rounds, are the
  levers to try.
