# M3 notes: golden set and L1 retrieval suite (2026-10-09)

## What was built

- **`golden/questions.yaml` v1:** 35 cases (30 answerable, 2 clarify, 4 out of scope). Every
  expected answer was checked against the indexed docs, and against config or code where the
  docs disagree. The maintainer ruled on HW-005, INST-001 and VER-002; VFR-001 was settled by
  reading the code. Nine documentation defects are recorded in `golden/README.md`.
- **`trap_sources`:** stale or misleading documents that produce a confident wrong answer if
  retrieved. L1 fails a case when a trap outranks every gold source, and attribution (M5) uses
  this to blame the corpus rather than the agent.
- **`lab/harness/`:**
  - `golden.py`: strict schema; a misspelled field is an error.
  - `l1.py`: scoring as pure functions, unit-tested.
  - `judge.py`: Haiku 4.5 for Ragas, with per-run token and cost accounting.
  - `VoiceLabLibrary.py`: the Robot Framework keyword library, which also acts as a listener.
- **`tests/L1_retrieval/L1_retrieval.robot`:** plain `robot tests/L1_retrieval` runs the suite.
  The library generates one test per answerable golden case, so no case is duplicated in
  `.robot` files. Two hand-written run-level tests check p95 latency and the aggregate
  thresholds.

Each generated case:

```
Search Docs                               (REST API, a separate process)
MCP Results Should Match REST             (MCP stdio session)
Score Retrieval With Ragas                (context precision and recall; records, never fails)
Retrieval Should Include Gold Source      (any gold source in the top k)
Trap Source Should Not Outrank Gold       (cases with trap_sources)
Top Hit Should Come From Expected Origin  (version cases)
```

Output: the Robot log and report, plus `results/L1/latest.json` and a timestamped copy with
run metadata (lab commit, the index commit of every source, embedding model, judge, judge
token usage and cost, thresholds), aggregates, and per-case results.

## Baseline (full corpus): `baselines/L1/2026-10-09.json`

32 tests: 26 pass, 6 fail. 5 min 19 s; judge cost $0.58 (180 Haiku calls, 409k input / 34k
output tokens).

| Aggregate | Value | Threshold |
|---|---|---|
| Hit rate (gold source in top 5) | 0.867 | 0.85 ✓ |
| MRR | 0.75 | — |
| Ragas context precision | 0.673 | 0.70 ✗ |
| Ragas context recall | 0.743 | 0.70 ✓ |
| Origin accuracy (version cases) | 1.0 | — |
| REST p95 | 76 ms | 300 ms ✓ |
| MCP matches REST | 30/30 | — |

Failures, all genuine findings rather than harness bugs:

| Case | Failure | Reading |
|---|---|---|
| HW-003 | trap above gold (1 vs 2) | The internal perf-branch doc outranks the README's Hardware section. |
| INST-001 | trap at 1, no gold in top 5 | The stale snap guide dominates "how do I install". The right sources (running from source, appliance guide) don't surface. |
| VER-002 | trap at 1, no gold in top 5 | The stale "development has not started" spec dominates "is there a moving map". |
| ARCH-002 | miss | "3490" sits in an appliance guide, a plugin doc and a config file; nothing is about the connection itself. |
| DEV-002 | miss | The README's *Testing* section is a 73-character stub. |
| Aggregate | Ragas precision 0.673 | Pulled down by the cases above, plus judge disagreements (below). |

Three of the six failures are **corpus problems**: a stale or internal document is the best
match for the question. Changing the agent or the retriever can't fix those; fixing the docs
can. That's the distinction the harness exists to make.

## For M4: judge disagreements to calibrate

Cases where the deterministic score and the judge disagree:

- **DATA-001:** a gold source was retrieved and Ragas recall is 1.0, but Ragas precision is 0.0.
- **DEV-003:** a gold source was retrieved at rank 1, but Ragas scores 0.0 / 0.25. The expected
  answer is a multi-step procedure spread across sections, so per-chunk precision may undercount it.
- **FGW-003:** the gold source is at rank 1 with recall 1.0, but precision is 0.2. The other four
  chunks are irrelevant, which is a fair score, but it shows precision@5 punishes single-source
  answers.

The plan's hand-graded calibration (~20 cases) should start with these. Precision@k with k=5
also caps low for questions that have one right section, so M4 should report precision
alongside MRR rather than threshold it alone.

## Engineering notes

- **Anthropic SDK 1.x vs Instructor:** SDK 1.x removed `temperature`, `top_p` and `top_k` from
  `messages.create()`, and Instructor 1.17, which Ragas uses, still sends `temperature` and
  `top_p`. Haiku 4.5 accepts one of them, so `lab/judge.py` moves `temperature` into
  `extra_body` and drops `top_p`, which keeps judging repeatable. Remove the shim when
  Instructor catches up.
- **Ragas 0.4.3** made its ID-based (no-LLM) context metrics private. The deterministic measures
  in `lab/harness/l1.py` replace them.
- **Robot and stdio:** Robot replaces `sys.stderr` with an object that has no `fileno`, so the
  MCP server's stderr goes to `results/mcp-server.log`.
- **Generated tests skip `--include`:** tag filtering runs before the listener adds tests, so the
  suite takes `-v L1_REPO:…` and `-v L1_IDS:…` instead.
- **CI** runs L1 on the cases its two-source index can answer, with the judge off and
  `--nostatusrc`. That checks the harness, not quality. Quality gating (a diff against the
  baseline) is M7. The Robot log is uploaded as a build artifact.
